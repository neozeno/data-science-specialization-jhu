Loops and Functions in R

In R, loops exist at two different abstraction levels:

  1. Imperative loops — you explicitly control iteration (for, while, repeat)
  2. Functional iteration — you pass functions into higher-order functions (apply, lapply, purrr::map, etc.)

The second style is heavily preferred in idiomatic R because:

  • R is vectorized
  • Functional iteration is usually shorter and safer
  • It avoid manual indexing bugs
  • Many operations are implemented internally with optimized C code

Think of it this way:

  • for loops = manually driving a car
  • apply family = using autopilot for common iteration patterns

Basic Loops in R

for Loop

Used when you know how many iterations you need.

numbers <- c(1, 2, 3, 4, 5)

for (n in numbers) print(n * 2)
[1] 2
[1] 4
[1] 6
[1] 8
[1] 10

Internals

R iterates through each element in the vector and binds it to n.

Equivalent mental model:

n <- numbers[1]
n <- numbers[2]

Index-based for

Useful when position matters.

numbers <- c(10, 20, 30)

for (i in seq_along(numbers)) {
    cat("Index: ", i, "Value: ", numbers[i], "\n")
}
Index:  1 Value:  10 
Index:  2 Value:  20 
Index:  3 Value:  30

Use seq_along() instead of 1:length(x) because it safely handles empty vectors.

while loop

Runs while a condition is true.

x <- 1

while (x <= 5) {
    print(x)
    x <- x + 1
}
[1] 1
[1] 2
[1] 3
[1] 4
[1] 5

Good for:

  • unknown iteration counts
  • polling
  • simulations
  • convergence algorithms

repeat loop

Infinite loop until explicitly stopped with break.

y <- 1

repeat {
    print(y)

    if (y == 5) break

    y <- y + 1
}
[1] 1
[1] 2
[1] 3
[1] 4
[1] 5

Useful for:

  • retry logic
  • event processing
  • iterative convergence

Control Statements

break

Stops a loop entirely.

for (i in 1:10) {
    if (i == 5) break
    print(i)
}
[1] 1
[1] 2
[1] 3
[1] 4

next

Skips current iteration.

for (i in 1:5) {
    if (i  == 3) next
    print(i)
}
[1] 1
[1] 2
[1] 4
[1] 5

Vectorization (Preferred Over Many Loops)

R is fundamentally vector-oriented.

Instead of:

result <- c()

for (i in 1:5) result[i] <- i * 2

Prefer:

result <- 1:5 * 2

This is:

  • cleaner
  • faster
  • memory efficient

The apply Family

The apply family abstracts iteration patterns.

apply()

Applies a function across rows or columns of matrices/data frames.

Syntax:

str(apply)
function (X, MARGIN, FUN, ..., simplify = TRUE)

Where:

  • X = matrix or array
  • MARGIN
    • 1 = rows
    • 2 = columns
  • FUN = function
  • ... = other args to pass to FUN
  • simplify = whether the simplify the result

Example: Column sums

mat <- matrix(1:9, nrow = 3)
apply(mat, 2, sum)
[1]  6 15 24

Example: Row means

apply(mat, 1, mean)
[1] 4 5 6

Important Limitation

apply() converts data frames into matrices.

This can cause type coercion.

Example:

df <- data.frame(
    a = 1:3,
    b = c("x", "y", "z")
)

apply(df, 2, class)
          a           b 
"character" "character"

Everything becomes characters.

Because of this:

  • apply() is best for numeric matrices
  • use lapply() for general lists/data frames

lapply()

Applies a function to each element of a list and returns a list.

Syntax:

str(lapply)
function (X, FUN, ...)

lapply take three arguments: (1) a list X, (2) a function (or the name of a function) FUN, and (3) other arguments via its ... argument. If X is not a list, it will be coerced to a list via as.list.

Example:

numbers <- list(a = 1:3, b = 4:6)

lapply(numbers, sum)
$a
[1] 6

$b
[1] 15

Key Characteristic

Always returns a list. This predictability is extremely important in robust programming.

sapply()

Simplified lapply().

Attempts to simplify the result of lapply().

sapply(numbers, sum)
 a  b 
 6 15

Instead of a list, it returned a vector.

Why sapply() Can Be Dangerous

Return types are inconsistent. Depending on data:

  • vector
  • matrix
  • list

This unpredictability can break production code. For reliable code:

  • prefer lapply()
  • or vapply()

vapply()

Safer version of sapply().

You explicitly define the output type.

Syntax:

str(vapply)
function (X, FUN, FUN.VALUE, ..., USE.NAMES = TRUE)

Example:

vapply(numbers, sum, numeric(1))
 a  b 
 6 15

This guarantees:

  • each result must be numeric
  • length 1

If not, R throws an error. This is very valuable in production systems.

mapply()

Multivariate apply. Applies a function to multiple inputs simultaneously. Equivalent to parallel iteration.

Syntax:

str(mapply)
function (FUN, ..., MoreArgs = NULL, SIMPLIFY = TRUE, USE.NAMES = TRUE)

Example:

mapply(sum, 1:3, 4:6)
[1] 5 7 9

Equivalent conceptual loop:

sum(1, 4)
[1] 5
sum(2, 5)
[1] 7
sum(3, 6)
[1] 9

Another Example:

mapply(
    function(x, y) x * y,
    c(1, 2, 3),
    c(10, 20, 30)
)
[1] 10 40 90

Map()

Wrapper around mapply() that always returns a list.

Map(
    function(x, y) x * y,
    c(1, 2),
    c(10, 20)
)
[[1]]
[1] 10

[[2]]
[1] 40

tapply()

Grouped apply. Applies a function over subsets defined by factors.

Syntax:

str(tapply)
function (X, INDEX, FUN = NULL, ..., default = NA, simplify = TRUE)

Where:

  • X = data
  • INDEX = grouping variable
  • FUN = function to apply

Example:

scores <- c(90, 85, 88, 70, 95)
groups <- c("A", "A", "B", "B", "B")

tapply(scores, groups, mean)
       A        B 
87.50000 84.33333

Equivalent SQL mental model:

GROUP BY groups
AVG(scores)

by()

Object-oriented version of tapply().

Used commonly with data frames.

by(
    iris$Sepal.Length,
    iris$Species,
    mean
)
iris$Species: setosa
[1] 5.006
------------------------------------------------------------ 
iris$Species: versicolor
[1] 5.936
------------------------------------------------------------ 
iris$Species: virginica
[1] 6.588

aggregate()

Very important for grouped operations on data frames.

aggregate(mpg ~ cyl, data = mtcars, mean)
  cyl      mpg
1   4 26.66364
2   6 19.74286
3   8 15.10000

Equivalent idea:

SELECT cyl, AVG(mpg)
GROUP BY cyl

split()

Splits data into groups.

split(mtcars$mpg, mtcars$cyl)
$`4`
 [1] 22.8 24.4 22.8 32.4 30.4 33.9 21.5 27.3 26.0 30.4 21.4

$`6`
[1] 21.0 21.0 21.4 18.1 19.2 17.8 19.7

$`8`
 [1] 18.7 14.3 16.4 17.3 15.2 10.4 10.4 14.7 15.5 15.2 13.3 19.2 15.8 15.0

Returns a list grouped by cylinder count.

Powerful Pattern

groups <- split(mtcars$mpg, mtcars$cyl)
lapply(groups, mean)
$`4`
[1] 26.66364

$`6`
[1] 19.74286

$`8`
[1] 15.1

This is effectively what tapply() does internally.

Modern Functional Iteration

From the tidyverse ecosystem.

Library:

library(purrr)

map()

Equivalent to lapply().

map(list(1:3, 4:6), sum)
[[1]]
[1] 6

[[2]]
[1] 15

Typed Maps

Safer and cleaner.

map_dbl(list(1:3, 4:6), sum)
[1]  6 15

Returns numeric vector.

Other variants:

  • map_chr()
  • map_int()
  • map_lgl()

map2()

Equivalent to mapply().

map2_dbl(c(1, 2), c(10, 20), ~ .x + .y)
[1] 11 22

pmap()

Generalized multi-input iteration. Useful for rows of data frames.

Performance Considerations

Historically:

  • loops in R were slow
  • vectorization was dramatically faster

Modern R has improved significantly.

Today:

  • preallocated for loops are often perfectly acceptable
  • badly written loops remain slow

Bad Loop

x <- c()

for (i in 1:10000) {
    x <- c(x, i)
}

Problem:

  • reallocates memory every iteration

Good Loop

x <- numeric(10000)

for (i in 1:10000) {
    x[i] <- i
}

This preallocates memory once. Major performance improvement.

Architectural Perspective

In real-world R systems:

  • Use vectorization first
  • Use apply family second
  • Use explicit loops when:
    • state changes between iterations
    • simulations
    • recursive algorithms
    • iterative optimization
    • sequential dependencies exist

Production-grade R code often favors:

vapply()
purrr::map_*()
data.table
dplyr

because:

  • types are predictable
  • pipelines remain composable
  • debugging becomes easier
  • behavior is more deterministic

Example: Data Pipeline Style

Traditional loop:

results <- numeric(length(groups))

for (i in seq_along(groups)) {
    results[i] <- mean(groups[[i]])
}

Functional style:

sapply(groups, mean)
       4        6        8 
26.66364 19.74286 15.10000

Modern tidyverse:

map_dbl(groups, mean)
       4        6        8 
26.66364 19.74286 15.10000

Same operation. Different abstraction levels.
